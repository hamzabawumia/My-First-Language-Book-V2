# Adding and Replacing Images

This guide is for developers working on **My First Language Book**.

The application is designed so that artwork can be added or replaced without changing the main application code.

---

## 1. Where the images live

All book artwork goes in:

```text
images/
```

The image filename is based on the picture's number in the book.

For example:

```text
images/
├── 001.jpg
├── 002.jpg
├── 003.png
├── 004.jpg
└── ...
```

---

## 2. Image naming convention

Images use three-digit numbers:

```text
001
002
003
...
200
```

Both **JPG/JPEG** and **PNG** are supported.

For example:

```text
001.jpg
002.png
003.jpg
004.png
005.jpg
```

The application checks for `.jpg` first. If the JPG does not exist, it checks for `.png`.

If both exist, the JPG is used.

### Do not use descriptive filenames

Do not name files:

```text
dog.jpg
my-dog.jpg
picture3.jpg
new-image.png
```

Instead use:

```text
003.jpg
```

The number is the connection between the vocabulary item and its artwork.

---

# 3. Replacing an existing picture

Suppose picture `003` currently contains a dog.

Replace:

```text
images/003.jpg
```

with your new image.

No JavaScript changes are required.

The application automatically looks for:

```text
images/003.jpg
```

and then:

```text
images/003.png
```

If neither file exists, the application falls back to the temporary placeholder.

---

# 4. Adding artwork for a picture

You do not have to create all 200 images at once.

For example, if picture 27 does not yet have final artwork, create:

```text
images/027.jpg
```

Once that file is uploaded, picture 27 will automatically use it.

You can gradually build the artwork library:

```text
001.jpg
002.jpg
003.jpg
...
027.jpg
...
100.jpg
...
200.jpg
```

---

# 5. Adding a completely new book item

Adding an image alone does **not** create a new book item.

The book items are defined in:

```text
data/vocabulary.json
```

Each item has an `id`.

For example:

```json
{
  "id": 151,
  "category": "animals",
  "concept": "..."
}
```

The ID determines the image filename:

```text
id: 151
```

corresponds to:

```text
images/151.jpg
```

or:

```text
images/151.png
```

### To add item 201

Add an entry to `data/vocabulary.json`:

```json
{
  "id": 201,
  "category": "animals",
  "concept": "..."
}
```

Then add:

```text
images/201.jpg
```

The application will use the new image for item 201.

---

# 6. Keep picture numbers stable

Once a number has been assigned, **do not casually change its meaning**.

For example, if the project defines:

```text
003 = dog
004 = banana
005 = cup
```

keep those assignments.

Avoid later changing them to:

```text
003 = banana
004 = dog
```

Stable numbering makes artwork management much easier and prevents the wrong image from appearing for a concept.

Think of the number as the permanent ID of the book item.

---

# 7. Image recommendations

The book is designed for young children, so images should be:

- Clear
- Large
- Easy to recognize
- Well lit
- Visually simple
- Free from unnecessary background clutter
- Consistent with the rest of the book

For an object such as a cup, the cup should occupy a substantial portion of the image.

For an action such as eating, the action should be immediately obvious.

## Do not put vocabulary words inside the images

For example, do not create an image containing:

```text
DOG
```

The book is intentionally language-neutral.

The parent supplies the word in the language they are teaching.

---

# 8. Recommended formats

### JPG

Recommended for photographic or realistic artwork.

Advantages:

- Smaller files
- Good for photographs
- Faster loading

Example:

```text
027.jpg
```

### PNG

Useful when:

- Transparency is required
- The image contains graphics
- Lossless quality is important

Example:

```text
027.png
```

You can mix JPG and PNG throughout the book.

---

# 9. Uploading through GitHub

To add an image directly through GitHub:

1. Open the repository.
2. Open the `images` directory.
3. Click **Add file**.
4. Select **Upload files**.
5. Upload the correctly numbered image.
6. Commit the change.

For example:

```text
Local file:
my-new-dog.jpg
```

Rename it before uploading:

```text
003.jpg
```

Then upload it to:

```text
images/003.jpg
```

---

# 10. Testing your image

After committing the image, open the GitHub Pages version of the application.

Navigate to the relevant picture number.

For example:

```text
27 / 200
```

Check that:

- The correct image appears.
- The image is sharp.
- The subject is easy to recognize.
- Nothing important is cropped.
- It looks good on desktop.
- It looks good on a phone/tablet.
- No vocabulary text has accidentally been included in the image.

---

# 11. The cover image

The cover is a special image.

It is stored as:

```text
images/cover_image.jpg
```

To replace the cover, simply replace that file.

No JavaScript changes are necessary.

---

# 12. PWA caching

The application uses a service worker:

```text
sw.js
```

The service worker caches application resources so the book can work offline.

The cache has a version number such as:

```js
const CACHE = "my-first-language-book-v6";
```

When making significant application changes, increment the version:

```js
const CACHE = "my-first-language-book-v7";
```

This tells the browser that a new version of the application should be installed.

If an updated image appears to be stuck in the old version, test the site in a private/incognito window or clear the site's cached data.

| Task | File/location |
|---|---|
| Replace picture 001 | `images/001.jpg` or `images/001.png` |
| Replace picture 050 | `images/050.jpg` or `images/050.png` |
| Add artwork for picture 75 | `images/075.jpg` |

| Change application behavior | `app.js` |
| Change appearance | `styles.css` |
| Change PWA caching | `sw.js` |

# Golden rule

> **The image filename is the book item's ID.**

If the vocabulary item has:

```text
id = 42
```

the artwork should be:

```text
images/042.jpg
```

or:

```text
images/042.png
```

You should **not modify `app.js` just to replace artwork**.

---

## Example: adding picture 042

Suppose the team has finalized the artwork for item 42.

Create:

```text
images/042.jpg
```

Upload it to GitHub.

That's all that is required if item 42 already exists in `data/vocabulary.json`.

The application will automatically find and display the image.

---

## Example: replacing picture 042

Delete or replace:

```text
images/042.jpg
```

with the new artwork.

Keep the filename:

```text
042.jpg
```

No application code needs to change.

---

## Developer checklist

Before committing new artwork:

- [ ] Correct three-digit filename
- [ ] Number matches the vocabulary item's `id`
- [ ] JPG or PNG format
- [ ] Main subject is clear
- [ ] Image does not contain written vocabulary
- [ ] Image looks good on desktop
- [ ] Image looks good on mobile
- [ ] Existing picture number has not been accidentally changed
